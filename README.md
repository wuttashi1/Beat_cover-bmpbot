# STUDIO BOT — обложки, BPM и MP3

Telegram-бот на python-telegram-bot 20.0. Запуск объединённого бота: `python main.py` или `python bot.py`.

## Меню

- **Обложки** — загрузка картинки, параметры, личные пресеты, оригинальные VEVO / EXPLICIT, повторная обработка.
- **BPM и таймкоды** — расчёт по структуре 4/4, свои и общие пресеты, пересчёт существующей структуры с другим BPM. Старые команды `/savepreset`, `/mypresets`, `/loadpreset`, `/deletepreset`, `/presetshop`, `/loadshared`, `/save_to_shared` работают.
- **MP3 и публикация** — существующий разбор названия, редактирование тегов, обложка и публикация для разрешённых пользователей. MP3 принимается и как аудио, и как документ.
- **Бот** — уведомления о перезапуске. Админ-панель остаётся доступна администратору.

`/menu`, `/cancel` и кнопка «Главное меню» отменяют текущий ввод. Выход из раздела также отменяет незавершённый MP3-черновик.

## Обложки

1. Открой «Обложки». Старые настройки пользователя автоматически становятся его текущим профилем при первом обращении к редактору.
2. В «Параметры обложки» выбери композицию, водяной знак, цвет или экспорт. Нажми параметр и выбери значение либо введи число.
3. Каждое изменение сразу сохраняется в SQLite. Чтобы сохранить отдельный вариант, нажми «Сохранить обложку как пресет». В «Мои обложки» можно применить, переименовать или удалить его с подтверждением. Одинаковые имена не перезаписываются.
4. Отправь JPEG, PNG или WebP как фото или документ (до 19 МБ, до 30 мегапикселей). По умолчанию результат — файл 1920×1080, без дополнительного сжатия Telegram.
5. Измени параметры и нажми «Пересобрать обложку»: бот использует последнюю успешно обработанную картинку этой сессии. После перезапуска нужно прислать исходник заново; профиль и именованные пресеты сохраняются.

Параметры: 1280×720 / 1920×1080 / 2560×1440; заполнение с обрезкой или вписывание VEVO; центр обрезки; Spin / Gaussian / однотонный фон EXPLICIT; размытие и яркость фона; размер и положение центрального фото; включение, размер, положение, отступ и непрозрачность знака; яркость, контраст, насыщенность, резкость; имя файла, JPEG / PNG / WebP, качество JPEG / WebP, отправка файлом / фото / обоими способами. Размеры в пикселях относятся к холсту 1920×1080 и масштабируются при экспорте.

Кнопки «VEVO — оригинал» и «EXPLICIT — оригинал» восстанавливают исходную композицию и параметры. Исходные алгоритмы и PNG-знаки сохранены; совпадение изображения при исходных настройках проверяется попиксельно. Именованные пользовательские варианты при этом сохраняются.

Выбор PNG/WebP относится к **файлу**. В режиме «Фото» отправляется JPEG-предпросмотр, который Telegram дополнительно сжимает. Для точного размера и формата используй «Файл» или «Фото + файл».

## Запуск и обновление

Python 3.11+:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py
```

### CasaOS / Docker Compose

Клонируй нужную ветку в `/DATA/AppData/studio-bot/app`, создай `.env` из примера и запусти `docker compose up -d --build`. `compose.yaml` хранит базу и пресеты в `/DATA/AppData/studio-bot/data`, поэтому обновление образа не стирает их. Контейнер появится в списке CasaOS и будет автоматически перезапускаться.

Одновременно должен работать только один экземпляр с тем же Telegram-токеном. Перед первым запуском новой версии останови старый контейнер. Если нужны прежние пользователи и пресеты, скопируй рабочие `users.db` и каталог `presets` в `/DATA/AppData/studio-bot/data` до запуска.

Заполни в `.env` существующие `BOT_TOKEN`, `ADMIN_USER_ID` и `PUBLISH_CHANNEL`; `ADMIN_USERNAME` необязателен.

Перед обновлением останови текущий процесс и сделай копию **его рабочих** `users.db` и `presets/`. Используй ту же базу и каталог пресетов: версия добавляет таблицы `cover_profiles` и `cover_presets` к существующей базе и не удаляет пользователей или BPM-пресеты. Не заменяй рабочую базу файлом из репозитория. При миграции колонок настройки читаются по именам, поэтому порядок старых колонок не влияет на результат.

Необязательные пути:

```dotenv
BOT_DB_PATH=/data/users.db
BPM_PRESETS_DIR=/data/presets
```

Без этих переменных используются прежние `users.db` и `presets/` в рабочем каталоге процесса. В Docker смонтируй соответствующие файлы/каталоги в постоянный том и укажи эти пути; одного слоя контейнера недостаточно для сохранения данных при его пересоздании. Старые данные нужно перенести в том перед запуском.

## Проверки

```sh
python -m unittest discover -s tests -v
```

Тесты используют временную базу, временные BPM-пресеты и имитацию Telegram API: не запускают polling, не отправляют сообщения и не публикуют в канал. Проверяются миграция и изоляция данных, сохранение после повторного открытия базы, CRUD пресетов, реальная маршрутизация ConversationHandler, отмена ввода, BPM и повторный расчёт, исходные стили, EXIF, размеры и форматы файлов. Живой запуск в Telegram требует токена владельца.
